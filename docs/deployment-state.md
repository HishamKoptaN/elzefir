# حالة النشر وسبب تأخر التحديثات

## كيف يعمل سير النشر

- الملف `.github/workflows/ci-cd-pipeline.yml` يعمل عند أي push، ويستدعي سير الاستضافة المشترك `50-firebase-hosting.yml`.
- عند الدفع إلى `dev`: البناء بـ `flutter build web --release --dart-define=ENV=dev`، ثم النشر إلى مشروع Firebase `elzefir-dev` → `https://elzefir-dev.web.app/`.
- عند الدفع إلى مصدر النشر الحي: البناء بـ `ENV=prod`، ثم النشر إلى موقع الاستضافة `elzefir` في مشروع Firebase `elzefir` → `https://elzefir.web.app/`.
- لذلك ظهور تغيير على نطاق التطوير لا يعني ظهوره تلقائياً على النطاق الحي؛ كل نطاق يُبنى من مصدر مختلف.

## الكاش ليس السبب

`firebase.json` يضبط `Cache-Control: no-cache, no-store, must-revalidate` لكل من `index.html` و`flutter_service_worker.js`، و`no-cache` لملفات `js/mjs/wasm`. تأخر الظهور سببه مصدر البناء لا الكاش.

## قاعدة التعامل

تحديث النطاق الحي يتطلب أمراً صريحاً ومباشراً من المستخدم؛ هذا الملف يوثّق الحالة فقط ولم يُجرَّ أي دمج أو دفع باتجاهه.
